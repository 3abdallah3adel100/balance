# balance-main: engine-only budget + API update

اتنقل **لوجيك الحساب والسحب فقط** من آخر نسخة Meta WhatsApp Smart Reports إلى مشروع balance-main المرفوع.

## ملفات المشروع التي اتغيرت
- `meta_api.py`: نفس قاعدة حساب الميزانية المعتمدة + سحب سريع للمصروف من Ad Insights في استعلام واحد، تخطي جرد الحسابات ذات الصرف صفر، مشاركة تهدئة الطلبات بين الـ Workers، ووقف الطلبات المتكررة عند Meta Error 17.
- `run_reports.py`: اكتشاف الحسابات من غير إعادة سحب الـ Business edges مرتين، وسحب الحساب بمتغير Token مصرح له، ومنع الـ Retry غير الضروري عند quota، واستخدام live budget في فاتورة الشحن لـ3 أيام.
- `budget_policy.py`: ملف جديد لحساب الميزانية على مستوى المالك (CBO Campaign أو ABO Ad Set) بدون تكرار.

## بدون أي تعديل على شكل الرسائل
الملفات `reports.py`, `whatsapp.py`, `app.py`, `config.py` والـ Workflows الأصلية متطابقة 100% مع الملفات الموجودة في ZIP المرفوع.
يعني نفس نص واتساب والتقسيم/الألوان/الأيقونات ونفس المستلمين، ولا تم إضافة سطر جديد للتقرير.

## قواعد الحساب
- الميزانية Live فقط إذا **Campaign + Ad Set + Ad** حالتهم effective ACTIVE، وصرف مالك الميزانية مبلغًا موجبًا في اليوم.
- CBO يتحسب على مستوى Campaign مرة واحدة، وABO على مستوى Ad Set مرة واحدة، بدون الجمع بين CBO والأبناء.
- Daily Budget المعروض في رسالة التقرير القديمة = Live Daily Budget + مبلغ الصرف الخاص بمالكي الميزانية **الذين توقفوا بالكامل** اليوم.
- صرف Ad واقف داخل Ad Set لسه شغال لا يضاف فوق ميزانية الـ Ad Set؛ ونفس القاعدة على الـ CBO Campaign.
- `live_daily_budget` متاح بالبيانات في الـ snapshot للتقارير الأخرى، لكنه لا يُعرض كسطر إضافي حتى يظل الشكل مطابقًا للقديم.
- تغطية الرصيد ومبلغ إعادة الشحن لـ3 أيام يعتمدان على Live Daily Budget فقط، لأن الصرف القديم لا يمثل مصاريف ستستمر مستقبلًا.
- إذا Metadata غير متاحة والسبب أخطاء API، يفشل السحب بدل إرسال إجمالي ناقص.

### مثال
- Ad Set شغال بميزانية 1000، وفيه إعلان داخله اتقفل بعد صرف 70: `live=1000`, `daily=1000`.
- Ad Set مستقل آخر اتقفل وصرف 150: `live=1000`, `daily=1150`.
- لا تظهر الميزانية المخصصة للـ Ad Set أو Campaign المقفولة؛ يظهر صرفها الفعلي فقط.

## الاختبارات

```bash
pip install -r requirements.txt

```

## تنزيل ورفع المشروع
يمكن رفع المشروع الكامل من ZIP، أو استبدال `meta_api.py` و`run_reports.py` وإضافة `budget_policy.py` فقط. لا تحتاج تعديل `reports.py` أو إعدادات الواتساب.

### قبل الإرسال الحقيقي
شغّل Action مع `dry_run=true` (الموجود أصلاً) وقارن الأرقام في Logs. بعد التحقق شغّله بـ `dry_run=false`.
لو Meta Token أصلًا واقع تحت Rate Limit، الإصلاح لا يلغي حظر Meta، لكنه يقلل الطلبات ويوقف إعادة المحاولة الضارة. لا يوجد زمن تشغيل مضمون وقت ضغط API.
